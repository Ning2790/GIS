## 二、任务卡

### N1 · 待支付订单超时自动取消 `P0`
- **缺口**：下单即扣 DB 库存（条件 UPDATE 防超卖），取消只由买家手动触发；未支付订单永久占用库存、支付单长期停在 `created`。
- **改动范围**：`backend/app/modules/shop/`（models / repository / service）+ 迁移（`orders` 建议加 `expire_at` 与 `cancel_reason`）+ `backend/app/worker.py`（Beat 任务 `shop.expire_unpaid_orders`）+ `backend/app/core/config.py`（`ORDER_EXPIRE_MINUTES`，默认 30）+ 测试。
- **要点**：
  - 复用 C4 取消语义：**原子条件更新** `status=created → cancelled`（与买家手动取消并发时只有一个生效）；库存同事务回补 + 库存流水（新增 `InventoryReason.EXPIRE` 以区分买家取消）；提交后按 DB 权威值同步 Redis 闸门；支付单同步置 `failed`。
  - 审计动作 `order.expire`；**注意** `admin.service.record_action` 的 `actor_id` 当前为必填 int——需扩展为 `int | None`（系统动作）或先约定空值语义。
  - 扫描走 `status=created AND created_at < now - N 分钟`；如量大补 `(status, created_at)` 复合索引。
- **验收判据**：超时订单自动取消、库存回补、流水与审计正确；任务重复执行幂等；并发 e2e（超时任务 × 买家手动取消）只生效一次；`make lint && make test` 绿。
- **完成**（2026-10-14，PR #17）：`orders.expire_at` + `cancel_reason`（默认 30 分钟，`ORDER_EXPIRE_MINUTES`）；`expire_unpaid_orders` 原子条件更新 + 同事务回补 + 流水 `expire` + 支付单置失败 + 审计 `order.expire`（系统动作 `actor_id=None`，审计表放开非空）；Beat 每分钟扫描 + `scripts/expire_orders.py`；前端展示支付截止与「已取消（超时未支付）」。实测：下单 → 拨过期 → 脚本取消 1 单、库存回补、审计与流水正确；pytest 163 全绿。
- **依赖**：无。
