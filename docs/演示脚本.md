## 一、演示前准备（提前 10 分钟做）

```bash

cd backend && uv run uvicorn app.main:app --port 8000 &   # 后端
```

## 二、完整演示流程

### 幕一 · 游客端（约 9 分钟）

**1. 首页与定位**（截图 `01-home.png`）
- 操作：打开统一门户 `localhost:5175`，用演示游客登录，自动回到游客端首页。
- 讲解要点：平台解决四类问题——游客不了解青海、农户卖不出、企业买不到、行前不知带什么；四个入口对应四大功能板块。底部「后端连接正常」是健康检查（演示环境所有服务真实运行）。

**2. 景点与地图**（截图 `02-attractions.png`、`03-map.png`）
- 操作：进入「景点」看卡片与门票；进入「地图」切换 卫星/行政/地形 三图，拖动地图看右侧点位列表联动，点「详情」跳到景点。
- 讲解要点：地图按视野范围（bbox）从后端拉点，PostgreSQL 用 PostGIS 空间索引查询；点位与景点库是同一份数据。

**3. 精选路线与一键套用**（截图 `04-routes.png`、`05-route-detail.png`）
- 操作：进入「精选路线」，用主题标签筛选（环湖/人文/摄影），打开「青海大环线 5 日精华」，说明每日安排与**全程约 1141.9 公里**（由 C++ 计算核心按停靠点坐标累加），点「套用为我的行程」。
- 讲解要点：路线是平台维护的资产，套用是**复制**一份到个人行程，之后互不影响；距离计算走 C++ 扩展，未编译环境自动回退 Python（两套实现有测试保证一致）。

**4. 行程编辑与风险提示**（截图 `06-plan-detail.png`）
- 操作：在行程详情里点「编辑停靠点」，调整顺序 / 换天 / 删除 / 新增，保存。
- 讲解要点：行程由 AI 按天数、预算、偏好、体力生成（mock 模型返回确定性结果，接真实模型只改 `.env`），风险提示有兜底文案；「全程约 231.8 公里」随停靠点变化实时更新。

**5. 行前装备建议**（截图 `07-gear.png`）
- 操作：进入「装备建议」，选城市与日期查看。
- 讲解要点：结合气温 / 土壤湿度 / 海拔 / 气压给出装备清单；数据由 Celery 每天早 6 点采集，已接 **Open-Meteo 真实气象源**（免密钥；断网自动回退模拟源，卡片右下角标注当前来源）。

**6. AI 助手**（截图 `08-ai.png`）
- 操作：进入「AI 助手」，点一个预设问题（如「高原反应怎么预防？」），展示**流式输出**。
- 讲解要点：SSE 流式（fetch 流读取）；**RAG 向量检索**（N12：向量优先、关键词兜底，命中时答复下方展示「参考平台知识」卡片，含主题与语义匹配分）+ 联网搜索适配器；当前为本地 mock，回答会标注「当前为模拟回复」。
- 建议演示问题：**「带小孩去青海要注意什么」**——关键词匹配不到（知识条目里没有「小孩」二字），向量检索经同义词归一命中「亲子出行」，可现场对比说明语义检索的价值。

**7. 商城下单（含商品图 + 收货信息）**（截图 `09-products.png`、`10-product-detail.png`）
- 操作：进入「特产商城」，展示商品图；打开「祁连山牦牛肉干」→ 立即购买 → 填收货信息（可从「个人中心 → 收货地址」带出常用地址）→ 得到待支付订单。
- 讲解要点：商品图经受控上传（类型白名单、匿名可读、私有文件仍受保护）且**上传即压缩、列表页走缩略图**；下单用**幂等键**防重复提交、Redis 预扣 + 数据库条件更新**双保险防超卖**。
- 加演（30 秒）：点搜索框下的**热门搜索**胶囊（如「雪菊」）直接出结果；
  详情页点**收藏** → 个人中心「我的收藏 / 浏览历史」→ 回首页看**「为你推荐」**
  已按刚才的行为变过（讲解：推荐分 = 名称相关性（C++ 打分核心）+ 价格接近度，游客按全站热度兜底）。

**8. 取消订单（库存回补）**（截图 `11-order-detail.png` 为已支付态）
- 操作：打开刚下的待支付订单 → 点「取消订单」→ 二次确认 → 状态变「已取消」，提示库存已回补。
- 讲解要点：取消是**原子状态翻转**（并发双击只有一次生效），库存回补与状态变更同一事务；该动作**写入审计日志**（管理端可查）。

**9. 申请售后单**（截图 `22-aftersales-tourist.png`）
- 操作：打开一笔已完成（或已支付）订单 → 「申请售后」→ 选问题类型 + 填说明 → 提交 → 跳转售后详情；再进「我的售后」看列表（待商户处理 / 处理中）。
- 讲解要点：售后单独立成单（**申请 → 商户受理 → 完成 / 拒绝**，受理前买家可撤销），双方可留言跟踪；平台不碰资金，退款 / 换货线下或走第三方；**在线客服仍是独立入口**（急事可直接找客服）。

**10. 个人中心（含登录设备）**（截图 `12-profile.png`）
- 操作：顶栏「个人中心」→ 改昵称（顶栏立即更新）→ 展示「登录设备」卡片（本设备 / 其他设备，可逐个移除）→ 演示改密码提示。
- 讲解要点：改密码会**撤销其他设备登录**并为当前端换发新令牌（安全设计）。

**11. 在线客服**（截图 `13-cs.png`）
- 操作：展示刚才的售后会话（AI 已自动应答），点「转人工客服」排队。
- 讲解要点：AI 应答失败会自动转人工兜底；队列按进入时间公平排序。

### 幕二 · 管理端（约 7 分钟）

**1. 概览（经营看板）**（截图 `14-dashboard.png`）
- 操作：打开统一门户（`localhost:5175`），用管理员登录（选「商户」入口），自动进入控制台概览页。
- 讲解要点：一张接口按角色返回不同字段——管理员看全平台，商户看自己的；含今日成交、库存预警、待审核、客服排队与最近操作（审计）。管理员还会多一张**运行指标卡片**（累计请求 / P95 延迟 / 限流命中 / 排队拒绝 / 在途与容量，与 `/metrics` 同源）。
- *也可以切商户账号再打开一次概览，说明两套视图的差异。*

**2. 商品管理（商户视角）**（截图 `19-products-merchant.png`）
- 操作：进入「商品管理」：展示主图、状态筛选（在售/已下架）、「编辑」（改价 / 库存 / 换图）、「上架商品」（含图片上传）、上/下架。
- 讲解要点：编辑是**部分更新**（只改提交的字段）；图片走公开图片机制，**上传即压缩并生成缩略图**（传一张大图会提示「原始 → 存入」），列表用缩略图、详情页用原图；商户只能改自己的商品（他人 403、界面不显示入口）。

**3. 订单与履约**（截图 `15-orders.png`）
- 操作：进入「订单管理」（管理员视角可模拟支付回调）：对刚才那笔待支付订单点「模拟支付成功」→ 状态变「已支付」；切商户账号，对已支付订单点「发货」（填承运商 + 运单号）→ 「标记签收」。
- 讲解要点：真实环境由第三方支付网关回调（平台只记录状态、不碰资金）；履约是 `created → paid → shipped → completed` 状态机，**签收后 7 天未确认收货自动确认**（Celery 每小时扫描）；每个动作都写审计。

**4. 售后管理**（截图 `21-aftersales-console.png`）
- 操作：进入「售后管理」→ 打开一笔「待处理」售后 → 「受理」并回复一条留言（买家端状态变「处理中」）→ 说明也可「完成 / 拒绝（理由必填）」。
- 讲解要点：售后台账按状态筛选；商户只能看到与自己订单相关的售后；留言双方可见、全程留痕。

**5. 资质审核**（截图 `17-reviews.png`）
- 操作：进入「资质审核」，展示待审核的「青海湖畔农牧合作社」，说明通过 / 驳回。
- 讲解要点：商户与企业注册需营业执照等资质，**审核通过前不能登录**（可在统一门户选「商户 / 企业」入口，用待审核账号现场演示登录被拦截）。

**6. 路线管理**（截图 `16-routes-manage.png`）
- 操作：进入「路线管理」，展示列表；点「新建路线」演示停靠点编辑器（景点下拉 + 第几天 + 备注），说明保存后游客端立即可见。
- 讲解要点：路线从"改脚本"变成运营后台可维护；停靠点顺序由服务端推导，增删改都会留审计。

**7. 客服工作台**（截图 `20-cs-workbench.png`）
- 操作：切换到商户账号（或管理员保留查看），进入「客服工作台」，看到人工队列里的会话 → 点「接入」→ 回复一条消息 → 结束会话。
- 讲解要点：接入是**原子抢占**（两个客服同时点只有一个成功）；每一步流转都进审计。

**8. 审计日志**（截图 `18-audit-logs.png`）
- 操作：回到管理员，进入「审计日志」：按动作或目标类型筛选（用户 / 订单 / 支付单 / 预设路线 / 客服会话 / 售后单）。
- 讲解要点：管理员操作、客服流转、业务动作（取消订单 / 支付回调 / 路线增删改 / 发货签收 / 售后流转）全部留痕，含操作人、目标与可读详情；日志与业务变更**同一事务**写入（不会出现"状态变了但日志丢了"）。

### 幕三 · 技术亮点（约 3 分钟，答辩加分项）

按需挑选 2–3 个讲，不要全讲：

1. **并发正确性**：`make e2e` 是一套跑在真实 PostgreSQL + Redis 上的并发回归（14 例）——幂等下单（4 并发只扣 1 次库存）、匹配冲突、购物车累加、令牌轮换等；曾经抓出并修复了"flush 点抛 IntegrityError 绕过回放"这类潜伏 bug。
2. **承载能力**：限流（登录按 IP / 下单按用户）+ 排队闸门（超载排队、交易优先，**容量与连接池对齐**）+ 热点缓存 + 多实例网关（least_conn）；压测报告见 `docs/压测报告.md`——三档实测（读 1189 req/s / 交易 81 单/s / AI 5.4 次/s），双实例同口径 1.53×，网关单 IP 限流约 30 req/s。
3. **C++ 计算核心**：距离 / 推荐打分 / 行程选点 / 路径总里程四个函数经 pybind11 暴露，未编译环境自动回退 Python（有一致性测试），CI 不需要编译器。
4. **工程质量**：后端 **236** 项单测（覆盖率 93.7%，门禁 88%）+ 14 项并发 e2e + 前端 **81** 项 vitest + 3 条浏览器 E2E 冒烟，三层 CI 全绿；`docs/需求对照表.md` 可逐条回答"需求在哪实现的"。
5. **可观测性与部署**：`/metrics` + 管理员概览运行指标卡片 + `X-Request-ID` 请求追踪（网关日志与后端日志同 ID 对齐）；后端与定时任务已容器化（`make full-up` 一条命令起全栈）。

## 三、精简版（3 分钟，找不到状态时用）

1. （30 秒）游客端下单：商城 → 商品 → 立即购买（点明"有图 + 防超卖 + 幂等"）。
2. （30 秒）取消订单：订单详情 → 取消 → 提示库存回补（点明"原子翻转 + 审计"）。
3. （40 秒）精选路线：打开一条路线 → 全程里程 → 套用为我的行程（点明"AI + C++ 计算核心"）。
4. （50 秒）管理端概览 → 订单管理点「模拟支付成功」/ 发货签收 →（30 秒）售后管理受理一笔售后 → 审计日志看到刚才的取消、回调与售后流转。
5. （10 秒）收尾：技术栈一句话（FastAPI + Vue3 + PostgreSQL/Redis/MinIO + C++ 核心，三层 CI 全绿）。

## 四、应急与常见问题

| 现象 | 处理 |
|---|---|
| 页面打不开 / 接口 502 | 检查后端 8000 是否在跑（`curl localhost:8000/api/v1/health`）；管理端清掉后端，重启 `uvicorn` |
| 登录提示「请求过于频繁」 | 登录限流（按 IP），等 3 秒重试即可；别连续快速登录 |
| 数据被演示改乱 | 重跑第一节的 seed 脚本（幂等）；订单类数据可用演示账号重新下单 |
| 商品图不显示 | MinIO 容器是否在跑；`docker compose up -d` 后在 backend 目录重跑 `uv run python scripts/seed_shop.py` 补图 |
| 忘了讲某页 | 截图在 `docs/screenshots/`，按编号即为推荐顺序 |
